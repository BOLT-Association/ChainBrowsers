# Target browsers

| # | Browser | Repo | Stack | Notes |
|---|---------|------|-------|-------|
| 1 | Hodos Browser (desktop) | https://github.com/BOLT-Association/Hodos-Browser | CEF C++ shell, Rust wallet (Actix, SQLite), React/Vite frontend | Keys stay in the Rust process. BEEF/SPV via a background monitor. Endpoints: WhatsOnChain, GorillaPool; port config in `cef-native/include/core/PortConfig.h`. Run with `HODOS_CHAIN_MODE=spv HODOS_ARCADE_URL=http://localhost:8080 HODOS_CHAINTRACKS_URL=http://localhost:8083/chaintracks/v2` (branch `arcade-provider`). spv mode uses only Arcade and a wallet-verified header chain, never public indexers or Teranode; raw txs and outputs arrive in BEEFs via `internalizeAction`. Default `public` mode is unchanged. |
| 2 | BSV Browser (mobile) | https://github.com/BOLT-Association/bsv-browser | React Native / Expo, WebView + CWI provider, SQLite wallet | Chain endpoints are env-configurable: `EXPO_PUBLIC_ARC_URL`, `EXPO_PUBLIC_CHAINTRACKS_URL` (and `_TEST_` / `_TERATEST_` variants); supports mainnet/testnet/teratest. Point at Arcade (`:8080`) and chaintracks (`:8083/chaintracks/v1`, which is what the toolbox client reads). Arcade has no `/v1` tx path and returns 202 on submit; the client accepts that. From an emulator/device use the host LAN IP, not localhost. The wallet core is the dependency `@bsv/expo-wallet-toolbox`, so changes are a `patch-package` patch. Run with `EXPO_PUBLIC_CHAIN_MODE=spv` plus `EXPO_PUBLIC_SPV_RULES=regtest` and an anchor (branch `spv-hardening`, [docs/bsv-browser-spv.md](../docs/bsv-browser-spv.md)): only Arcade and a wallet-verified header chain, no public indexers. Default `public` mode is unchanged. Regtest-only; not yet run on a device. |

Clone each into `browsers/<name>/` (gitignored; we integrate via patches or submodules, decided when work starts).
