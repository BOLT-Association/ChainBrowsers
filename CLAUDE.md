## Safety: running a wallet

- ⛔ **Never run `hodos-wallet` without redirecting its data dir.** On Windows the data dir comes from the known-folder API, **not** the `APPDATA` variable, so overriding `APPDATA` does nothing and the process would open the real `HodosBrowserDev` DB and migrate it. Use `HODOS_DEV=1` + `HODOS_DATA_DIR=<scratch dir>` (honoured only with `HODOS_DEV=1`).
- To test against a real DB, copy `wallet.db`, `wallet.db-wal` **and** `wallet.db-shm` together into `<scratch>\wallet\`, run on the copy, delete it afterwards, and check the real files' sizes/timestamps are unchanged.
- spv mode (`HODOS_CHAIN_MODE=spv`) makes no MessageBox/PeerPay traffic and no public-indexer calls, so a run on a copy cannot acknowledge real messages. Public mode does both.
- Stop only your own wallet process, matched by exe path (`*ChainBrowsers*Hodos-Browser*rust-wallet*target*debug*hodos-wallet.exe`); never by image name (the user's installed Hodos uses the same name).
- Build with `cargo` from bash (it is not on the PowerShell PATH); a running wallet locks `target\debug\hodos-wallet.exe`, so stop it before rebuilding.

## Verified findings (Oct 2026)

- **Browsers talk only to Arcade** (`:8080` API, `:8083` chaintracks headers, `:8082` SSE), never to Teranode. Arcade has no raw-tx, block, UTXO, address or outspend endpoint, so in spv mode outputs and parent txs arrive in BEEFs (`internalizeAction`) and are cached; address lookups return errors, never empty lists.
- **Arcade `POST /tx` accepts raw or Extended Format only, not BEEF.** Hodos converts BEEF to EF (needs the parents in the BEEF). It answers `202`; a coinbase an earlier run already spent is accepted for processing and then `REJECTED`, so wait for a network status before trusting it.
- **Arcade embeds go-chaintracks** (stores and serves headers, bulk `/headers`); no separate block-headers-service or chaintracks service is needed.
- **Arcade SSE** is a separate listener (default `:8082`, published by spv-testnet as `ARCADE_SSE_PORT`): frames `id:` / `event: status` / `data: {txid, txStatus, ...}`, `: keepalive` every 15 s, MINED frame carries `merklePath`, `Last-Event-ID` replay is best-effort. Only txs submitted with the same `X-CallbackToken` produce events.
- **First-seen:** a conflicting tx is `REJECTED` and the first stays `SEEN_ON_NETWORK`; Arcade never flags the first as a double-spend on a single node. A child of an unmined parent stays `ACCEPTED_BY_NETWORK` until a block.
- **After a machine restart the stack is down** (Docker Desktop is not running and some containers come back half-started): start Docker Desktop, then `stack.ps1 up -NoMine` in `spv-testnet/stack` (add the miner back with `docker start cb-block-generator`); `e2e.ps1` does both.
- **The stack's `cb-block-generator` mines every few seconds.** Scenarios that need an unmined tx (`fund-unmined`, `zero-conf`, `push-fallback`) must `docker stop cb-block-generator` first and mine by hand; restart it after.
- **The regtest subsidy runs out.** The miner makes a block every few seconds and regtest halves the subsidy every 150 blocks: by height ~2000 a recent coinbase holds under 1,000,000 sats, and at 4950 it is zero. `tests/hodos-spv/lib.mjs :: spendCoinbase` falls back to older coinbases; when those are used up the stack needs a `reset` (and both test wallets recreated).
- ⛔ **Do not start a Hodos spv wallet while Arcade is unreachable** if it has unproven transactions older than the proof timeout: it marks its own mined transactions failed and restores their inputs, and does not heal (`docs/issues/hodos-spv-outage-fails-mined-txs.md`; not fixed). After such a start, use a fresh scratch wallet.
- Arcade's fee policy reports 0 sat/KB, which Hodos's 100–10,000 sanity range rejects (it falls back to its default rate). Hodos derives mainnet-format addresses; the harness pays output scripts, not address strings.
- The balance cache is 60 s and `internalizeAction` does not invalidate it in public mode (spv mode does).
- In spv mode a MINED tx is confirmed only when a proof that verified against the wallet's own header chain is stored. A proof the header chain cannot judge yet (sync trails Arcade's MINED event by seconds) is **held** in the V27 `pending_proofs` table, never in `proven_txs` (every reader of that table treats a row as verified), and is verified locally after the next header sync with no re-fetch; wrong proofs are dropped, 6 h expiry. Push events carry the MINED `merklePath` into the same table. Header sync runs every 30 s, the proof poll every 60 s.

## bsv-browser: what to know before touching it

- **Where the code is:** the header store, chain tracker and proof storage are in `node_modules/@bsv/expo-wallet-toolbox/core/` (TypeScript source) and `@bsv/wallet-toolbox-mobile` (one bundle, `out/index.mobile.mjs`). The hardening is `patches/@bsv+expo-wallet-toolbox+0.11.0+001+spv-hardening.patch` (patch-package filenames use single `+`; `++` means a nested package). After editing files under `node_modules`, regenerate the patch from a diff against the pristine tarball (`npm pack @bsv/expo-wallet-toolbox@<version>`); `npx patch-package <pkg>` fails here (its temporary `npm install` of the package exits 1; cause not investigated). Prove it with `npm ci` in a scratch directory and a `diff -r` of `core/`.
- **Run live tests serially, by name:** `SPV_LIVE=1 npx jest __tests__/spv/live/headers __tests__/spv/live/wallet __tests__/spv/live/auth __tests__/spv/live/sse __tests__/spv/live/zeroconf --runInBand`. The reorg test invalidates blocks, which breaks the wallet test if they overlap, and the zero-conf test stops the miner. They stop `cb-block-generator` and start it again; check `docker ps` afterwards. Another Claude session may share the clone and the stack (it worked on `crosswallet.live.test.ts`, which also needs a running Hodos wallet): coordinate before running, never stage its files.
- **Live test wallets need a unique callback token each.** Arcade replays every past event for a token from `Last-Event-ID: 0`, so a shared token made SSE tests take 35-80 s while they drained other runs' events.
- **A child of an unmined parent is mined a block later:** after B (unmined, seen) is spent by C, one block mines B; C needs another. The toolbox broadcasts a payment it received unmined only after about 7 s (`TaskSendWaiting`).
- **`getblock` on this stack may omit `tx` for a 1-tx block:** use `block.tx?.[0] ?? block.merkleroot` for the coinbase txid (otherwise `getrawtransaction` fails with "invalid hash length").
- **jest-expo replaces `fetch`** with a polyfill that cannot reach localhost. Live tests use the environment `__tests__/spv/live/nodeEnv.cjs`, which hands them Node's real fetch.
- **The toolbox rejects non-mainnet chains in several places** (`ChaintracksServiceClient`, `hashToHeader`, the Arcade proof provider all check proof-of-work against the mainnet limit), so regtest needs the raw client, `hashToHeader` from the verified chain and the Arcade proof service in `core/spv/`.
- **The toolbox monitor checks headers against mainnet proof of work** (`copyValidatedMonitorHeader` in the mobile bundle), so on regtest `TaskNewHeader` failed every poll and nothing triggered the proof task in the app. `core/spv/monitorHeaders.ts` replaces the check with the chain's rules in spv mode. The headless tests run the proof task by hand, so only the app (emulator) shows this class of bug.
- **`TaskCheckForProofs`:** `checkNow` is a static flag; a proof whose validation fails inside `getCanonicalMerklePath` leaves no error note (only the provider's success note), so check `proven_txs` rather than the log.
- **Files from the published toolbox are LF; a Windows Python `open(..., 'w')` writes CRLF.** Use `newline=''` when scripting edits, and never put `\n` inside a non-raw Python string meant to be a JS string literal (it becomes a real newline).
- **Not mine, left alone:** `__tests__/vault/guard.test.ts` fails on a clean checkout (5 tests); `eas.json` commits WhatsOnChain API keys.

## Cross-wallet e2e (`tests/cross-wallet`): what to know before running it

- **It shows two real browsers:** the Hodos dev browser and the bsv-browser app in the Android emulator `xw_spv` (never `bsv_pixel`, which holds the user's own install). `start-hodos.ps1` starts the wallet first so the browser adopts it, with `HODOS_DATA_DIR` and `APPDATA` under `tests/cross-wallet/out/hodos`; `-Stop` matches by exe path.
- **Test artifacts go in `tests/cross-wallet/out/`** (gitignored): screenshots, logs, Hodos scratch data. Do not write them to `%TEMP%`.
- **Hodos pages, two rails:** `window.CWI` (and `window.BOLT`) are injected only into main frames of external `https://` pages, and their calls ride the **`wallet_call` IPC bridge** (`window.__hodos_walletCall` → `cefMessage` → C++ → the Rust wallet; `X-Requesting-Domain` is stamped natively and no endpoint list is checked on that path). A page that is not injected (plain http on loopback, like the cross-wallet test page) uses the older rail instead: `fetch('http://localhost:3321/<method>')`, which the browser intercepts and forwards with `X-Requesting-Domain: localhost:<port>`, but only for paths in `isWalletEndpoint` (`HttpRequestInterceptor.cpp`). Wallet errors come back as HTTP 200 with an `error` body. To test an injected page without internet, serve it yourself over https on a made-up name and start the browser with `start-hodos.ps1 -BrowserArgs '--host-resolver-rules="MAP bolt.test 127.0.0.1"','--ignore-certificate-errors'` (`packages/bolt/live/hodos-page.live.mjs` does this).
- **Hodos modals:** approve the domain with `POST /domain/permissions` (no domain header), but a `createAction` from a page still raises a payment modal when the browser has no BSV price. The modal's DevTools target keeps `…/brc100-auth?type=idle` as its URL while it shows a request, so detect it by its Approve button. DevTools is on `:9322` in dev builds; open tabs with `window.cefMessage.send('tab_create', url)` from the `http://127.0.0.1:5137/` target.
- **bsv-browser pages:** no wallet access from a page served from an IP address (use `adb reverse` and `localhost`); a page may not call `getPublicKey` with the BRC-29 protocol or list the `default` basket; `listOutputs` / `listActions` argument errors surface as "not permitted for origin".
- **Both wallets sync headers on Arcade's push.** Arcade's chaintracks has a tip stream, `GET :8083/chaintracks/v2/tip/stream` (SSE, no token: the present tip on connect, a `data:` frame with the full header per new block; only under `/v2`). Each wallet treats a frame as a trigger for its ordinary, validating header sync and then checks for proofs: Hodos in `tip_stream.rs` + `monitor/task_tip_stream.rs` (off with `HODOS_TIP_STREAM=off`), bsv-browser in `core/spv/tipStream.ts` + `announceChainTip`. A wallet has a new header 0.1 to 0.2 s after the push. The polls stay as the fallback (Hodos 30 s; bsv-browser 10 s in spv mode, `SPV_NEW_HEADER_POLL_MS`).
- **Metro runs with `CI=1`, which disables reloads:** after editing app code (including the toolbox under `node_modules`) restart Metro and the app (`e2e.ps1 -RestartMetro`), or the emulator keeps running the old code.
- **Android build on Windows:** JDK 17 and `ANDROID_HOME=C:\Android` in the shell (the stored `ANDROID_HOME` has a trailing newline); Metro on 8089 because Arcade's health port is 8081; `@bsv/react-native-localpay-transport` needs a short `buildStagingDirectory` (260-character path limit; snippet in `docs/cross-wallet-e2e.md`); a `subst` drive does not work with the Gradle settings. Pass the `EXPO_PUBLIC_*` spv settings as shell environment to Metro, not a `.env.local` (jest-expo would load it).
- **Hodos shell build:** `-DCEF_ROOT=` and `-DVCPKG_INSTALLED_DIR=` (with `-DVCPKG_MANIFEST_INSTALL=OFF`) can point at another clone's CEF binaries and vcpkg packages; `external/winsparkle` must exist in the clone being built.
- **The relay talks to one page per role** (the newest); stale tabs are told to stop. Kill a standalone `node server.mjs` before `run.mjs` (same port).
- **Each test page shows only its own wallet** (`say(text, kind, pages)` in `run.mjs`: console text plus a line per role) and the headers Arcade pushes (the page opens the tip stream itself and then asks its wallet how soon it has the block; in the emulator through `adb reverse tcp:8083`). `uiautomator dump` takes 5 s or more while the page is busy, so anything that reads the emulator screen during the test must not block (`watchToast` is async).
- **The test funds one wallet at random** (`FUNDED=hodos|bsv` fixes it); it pays the other 30,000, which pays 15,000 back. The test's own checks (`listActions`, `getHeight`) are asked with `quiet` and not listed on the pages. If a run stalls, look at the emulator first: a "isn't responding" dialog, or `adb devices` no longer listing it.

## BOLT (`packages/bolt`, `window.BOLT`): what to know before touching it

- **What it is:** the page interface for BOLT tokens (b017), beside BRC-100. `packages/bolt/src`: `handler.js` (the operations), `core.js` (what it needs from a wallet), `nft.js` / `fungible.js` (token building), `store.js` (the token table), `page.js` (page methods, prompt text), `browser.js` + `wallet-rail.js` (Hodos: handler in the page, network and tokens through the wallet), `webview.js` + `rn.js` (bsv-browser: thin page, handler in the app). Design, consent and what is verified: `docs/bolt-browser.md`.
- **b017** is cloned at `b017/` (gitignored; branch `async-signer` of `BOLT-Association/b017`) and reaches `packages/bolt` as a packed tarball: `npm run vendor`. After re-vendoring the same version, `rm -rf node_modules package-lock.json && npm install` (npm keeps the old tarball otherwise).
- **Two generated files live in the browser repos** and must be regenerated after any change to the handler, b017 or the bundlers: `npm run bundle` → copy `dist/BoltShimScript.h` to `browsers/Hodos-Browser/cef-native/include/core/`; `npm run bundle:rn -- ../../browsers/bsv-browser/vendor/bolt/bolt.js`.
- **MSVC caps a string literal at about 16 KB** (C2026 "string too big"; measured: 16 KB compiles, 24 KB does not), and the cap applies to adjacent literals joined by the compiler too. The Hodos header therefore holds the 425 KB script as separate ~16 KB literals joined at runtime.
- **Tests:** `npm test` in `packages/bolt` (headless, on a pretend chain that runs every script). Live scripts are in `live/` (never under `test/`, or `node --test` runs them with the stack down): `hodos.live.mjs` (wallet HTTP + Arcade), `hodos-page.live.mjs` (a real page in the Hodos browser), `bsv-page.live.mjs` (a real page in the app in the emulator). In Hodos: `cargo test --bin hodos-wallet bolt`. In bsv-browser: `npx jest __tests__/bolt`.
- **A scripted edit from Python on Windows writes the Windows codepage** unless `encoding='utf-8'` is given, and a `\n` typed inside a tool command reaches Python as a real newline. Both have corrupted files here; use the editor for anything with escapes or non-ASCII.

## AuthBOLT sign-in (PeerLoop + Hodos): what to know before touching it

- **Design and status:** `docs/authbolt-registration.md` (model, flow, what was built where). Users issue their own AuthBOLTs (a new key per identity, BRC-43 protocol `authbolt identity`); apps verify. A page can only `BOLT.list()` its own identities and `BOLT.requestPresentation({appPubKey, data, purpose, silent})`; minting and presenting happen in Hodos's own prompt (`BoltIdentityPrompt.tsx`), never in the page.
- **The live test is `node tests/authbolt/peerloop.live.mjs`** (stack up, Hodos started with `-BrowserArgs '--host-resolver-rules="MAP app.lab 127.0.0.1"','--ignore-certificate-errors'`, wallet funded, `p2p/results/p2pd.exe` built). It starts its own throwaway rqlite, fundd (the app's funding wallet, on :8098, seeded from a coinbase) and p2pd over https as `app.lab:8443` (it builds and starts boltverifyd; `VERIFIER=sidecar` starts the Node bolt-verify sidecar instead), and clicks the prompts through DevTools. Every token move is on chain and paid by fundd: registration (holder 1), a rotation p2pd asks for after `-rotate-after 60s` (holder 2), a reissue (holder 3), and an unposted move the wallet recovers from by signing with the holder the server names (no reissue). It waits out two rotation delays (~5 min in all). Negative controls, each must fail at registration: `NC_NO_VERIFIER=1` cuts the verifier off from Arcade and from p2pd's headers alike (an anchor already proven into p2pd's headers is never asked of Arcade); `NC_NO_FUND=1` runs p2pd without fundd. Each keeps its own logs (`*-nc-verifier.log`, `*-nc-fund.log`).
- **Verifier:** p2pd links no token-script code (zero deps; `labctl check` gate `zero-deps`) and always asks a verifier service (`-bolt-verify-url`, Bearer `-bolt-secret-file`). The default is **boltverifyd**, p2p's nested Go module `p2p/boltverifyd` (flags `-arcade-url`, `-headers-url`), on the Go port of b017 (`BOLT-Association/b017-native`, module `.../go`, package `authbolt`, pinned to 448de4a, which reads tag 04 too) plus its own mint-provenance check; the gate `boltverifyd` forbids it touching signature hooks. `p2p/testdata/contract/verify/recorded.json` holds real presentations and the sidecar's answers (`packages/bolt/scripts/record-verify-contract.mjs`), and `boltverifyd/contract_test.go` holds it to them. The Node sidecar (`packages/bolt/bin/bolt-verify.mjs`) gives the same verdicts.
- **Chain trust:** p2pd keeps its own verified header chain (`p2p/internal/headers`, Hodos's regtest rules) and answers the verifier's root questions on a loopback port (`-internal-addr`, Bearer secret); Arcade is asked only whether an anchor was seen.
- **PeerLoop has no passwords** (user, 2026-10-07: "No need for passwords, remove"). Old rqlite rows lose the `hash` column on migrate and cannot sign in. Lab browsers (Chromium, Firefox) have no wallet: lab tests check the no-wallet path, never a fake wallet. BSV Browser is set aside for now.
- **Generated files to refresh after changing `packages/bolt`:** `npm run bundle` (Hodos `BoltShimScript.h`, page shim) and `npm run bundle:identity -- ../../browsers/Hodos-Browser/frontend/src/vendor/bolt-identity.js` (the prompt's identity code). The overlay loads the latter lazily; keep it out of the overlay's main chunk.
- **The AuthBOLT icon** is the BOLT Association's mark from boltassociation.com (`frontend/public/authbolt.png`, `p2p/web/icons/authbolt.png`).
