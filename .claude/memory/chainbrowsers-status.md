**Intent (user, 2026-10-04):** Hodos spv mode is meant for testnet and mainnet through an EXTERNAL Arcade instance, not just the local regtest chain; the local `BOLT-Association/spv-testnet` stack (Teranode + merkle-service + Arcade) is only the test bed. Everything verified so far is regtest: header rules are `Params::regtest()` only, so spv mode cannot confirm anything on testnet/mainnet until per-network header params (genesis/checkpoint, DAA, MTP) exist. Other blockers for real use: no Arcade auth (API key/bearer) support, PeerPay/MessageBox is off in spv mode, wallet recovery/address sync need address lookups spv mode disables. Frame docs/PRs that way (the Hodos PR description was rewritten accordingly). ChainBrowsers connects browsers (Hodos desktop; bsv-browser mobile, not started) to that stack. Repo docs hold the detail: ChainBrowsers `CLAUDE.md`, `docs/hodos-spv.md`, `docs/roadmap.md`; spv-testnet `CLAUDE.md`. This note is only the state and the non-obvious bits.

**Branches / pushes (2026-10-03, after the user's explicit "commit and push"):** ChainBrowsers branch `docs/spv-testnet-refresh` (docs, `CLAUDE.md`, `tests/hodos-spv/`); Hodos clone `browsers/Hodos-Browser` branch `arcade-provider` on `BOLT-Association/Hodos-Browser` (based on org main = staging `3a22035d`; org `0.4.0` is stale, ignore the Hodos CLAUDE.md "rebase onto 0.4.0"); spv-testnet `main` (SSE port published). Nothing merged to ChainBrowsers/Hodos main. Open PRs (opened 2026-10-03 at the user's request): ChainBrowsers #1 (docs/tests) and Hodos-Browser #1 (spv mode), both into `main`.

**Hodos spv mode (`HODOS_CHAIN_MODE=spv`, needs `HODOS_ARCADE_URL` + `HODOS_CHAINTRACKS_URL`)** built and verified live on a real wallet process: Arcade for broadcast/status/BUMPs (BEEF converted to Extended Format; Arcade rejects BEEF), wallet-owned verified header chain (regtest rules only; V26 `header_chain` table; reorg handling; stored-proof recheck), BEEF BUMP verification in `internalize_action`, no public-indexer calls, no MessageBox traffic, `getHeight`/`getHeaderForHeight` from the verified chain, fund-by-BEEF + spend harness, Arcade SSE push (`HODOS_ARCADE_SSE_URL`, `HODOS_ARCADE_PUSH=off`; wake-up only, polling stays 60 s: working 0.7 s, refused 59 s, silent 62 s, dropped+restored 8.7 s), zero-conf spending of received outputs once seen on the network (`HODOS_ZERO_CONF=off` to disable; no amount cap, user chose the simple version).

**Open / known limits:** mainnet header rules (checkpoint, DAA, median-time-past) not built; double-spend withdrawal of a zero-conf output is unit-tested only (Arcade's first-seen rule never flags the first tx on one node); a child of an unmined parent stays ACCEPTED_BY_NETWORK so receiving a chain waits for a block; an internalized output whose tx is never mined is never cleaned up; no browser-settings toggles (env only); bsv-browser has none of this yet; Arcade fee policy 0 sat/KB is rejected by Hodos's fee sanity range (falls back to default); public-mode proof that fails verification still marks the tx confirmed (existing, left alone).

**Why:** Phase 1/3 of the roadmap: verify each browser's own SPV against the local chain. See [[browser-header-audit]], [[browsers-only-via-arcade]], [[working-rules-chainbrowsers]].
